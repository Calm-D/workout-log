# 训练日志 · 开发文档

> PC 测试版与 Android APK 均已完成。APK 位于 `release/WorkoutLog-v1.0.1.apk`；真机安装兼容性、锁屏通知与厂商省电策略仍需实机验证。
> 文档会随功能演进更新。

## 1. 项目概况

- 定位：个人使用的本地健身计划与训练记录 App，离线优先，无账号和云同步。
- 形态：同一套 React 前端，通过 Capacitor 打包为 Android APK。
- 当前入口：浏览器访问 `http://127.0.0.1:8014`；Android 安装 `release/WorkoutLog-v1.0.1.apk`。
- 应用名：训练日志；包名：`com.local.workoutlog`；版本 1.0.1；minSdk 24 / targetSdk 36。
- 工程目录：仓库根目录。

## 2. 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| UI | React 18 + TypeScript | 函数组件，路由页面 |
| 构建 | Vite 5 | 开发服务、生产构建 |
| 路由 | react-router-dom 6（HashRouter） | 适配 Capacitor WebView |
| 状态 | Zustand 4 + persist | 本地 localStorage，键名 `workout-log-data-v1` |
| 日期 | dayjs | 月历、格式化、相对日期 |
| 图表 | 自绘 SVG | 无 Recharts 等重型库 |
| 原生桥 | Capacitor 8 | LocalNotifications / Filesystem / Share / App / StatusBar |
| 测试 | Vitest + Playwright Core | 单元测试 + Edge 浏览器流程回归 |

没有使用 UI 组件库、图标库、动画库。图标为内联 SVG，动画为 CSS transition/keyframes。

## 4. 本地运行与构建

```powershell
cd workout-log
npm install
npm run dev
```

- 开发服务固定 `127.0.0.1:8014`，`strictPort`。
- `start.bat`：端口已占用则直接打开浏览器；否则隐藏启动 `npm run dev`，等待后打开浏览器。符合工作区脚本约定（两段式端口检测、纯 ASCII、CRLF）。
- `stop.bat`：通过 `netstat` 找 8014 监听进程并 `taskkill`。
- `npm run build`：先 `tsc --noEmit`，再 Vite 构建到 `dist/`。
- `npm run preview`：预览生产构建（同 8014）。
- `scripts\build-apk.ps1`：设置 JDK 21 / Android SDK，使用 `android/aliyun.init.gradle` 注入 Maven 镜像后执行 `assembleRelease`。
- APK 产物：`release/WorkoutLog-v1.0.1.apk`（约 3.36 MB）。

## 6. 数据模型

定义在 `src/types.ts`。

```ts
WorkoutPlan {
  id, name, note?, createdAt, updatedAt, lastUsedAt?, sample?,
  exercises: PlanExercise[]
}

PlanExercise {
  id, name, category?, note?,
  sets: PlanSetTarget[]   // 每组目标，支持逐组不同
}

PlanSetTarget {
  weightKg: number | null // null = 自重
  reps: number
  restSeconds: number
}
```

训练实例是计划的**快照**：

```ts
WorkoutSession {
  id, date: 'YYYY-MM-DD', planId?, planName,
  status: 'planned' | 'active' | 'completed',
  createdAt, startedAt?, endedAt?, note?,
  exercises: SessionExercise[]
}

SessionExercise {
  id, name, category?, order, note?,
  sets: SessionSet[]
}

SessionSet {
  id,
  targetWeightKg: number | null,
  targetReps, restSeconds,
  actualWeightKg?: number | null,
  actualReps?, status: 'pending' | 'done' | 'partial' | 'skipped',
  completedAt?, note?
}
```

其他：

- `BodyMetric`：日期 + 体重/腰围/胸围/臂围/腿围（均可选）+ 备注。
- `Settings`：默认休息秒数、完成一组是否自动休息、声音、震动、系统通知开关。
- `RestTimer`：休息倒计时的持久化状态（起止时间、下一组文案、通知 id、是否已调度）。
- `ExerciseDef`：动作库条目（胸/背/腿/肩/手臂/核心/其他）。
- Store 键：`workout-log-data-v1`，persist 版本 1。

## 7. 核心状态与业务规则

### 7.1 布局与导航

- 底部标签：日历 / 计划 / 趋势 / 我的；历史记录并入日历和当天页，不单独设 Tab。
- 训练页/动作页/确认页等为子页面，隐藏底部标签。
- 训练进行中离开训练页时，其他页面底部显示「训练中」悬浮条；休息中还会叠一条倒计时。

### 7.2 计划 → 当天训练

1. 用户在日历点今天/未来日期 → `/pick/date`。
2. 选计划 → `/confirm/plan/:planId/:date`。
3. 确认页修改重量/次数/休息：
   - **只改本次训练快照**，不改计划模板（使用 `createSessionFromPlan` 传入编辑后的临时计划对象，不调用 `savePlan`）。
4. 今天 → 「保存并开始训练」：创建 `active` session，写 `startedAt`。
5. 未来 → 「保存到日历」：创建 `planned` session。
6. 同一天已存在 `planned` 时，新排期会替换旧的 planned；已完成的记录不删除。

### 7.3 训练动作自由顺序

- 训练页按计划顺序展示动作，但每张卡都可以点击，不限制必须按顺序。
- 进入动作页即视为开始该动作的记录；不需要额外的「开始动作」按钮。
- 动作状态由组状态派生（`deriveExerciseStatus`）：
  - 全部 pending → 未开始
  - 部分处理 → 进行中
  - 全部处理且不全是 skipped → 已完成
  - 全部 skipped → 已跳过
- 所有组处理完后，动作页出现「动作已完成」卡片和「返回动作列表」。

### 7.4 组记录

- 点方框：把 pending 组按目标重量/次数记为 `done`，记录 `completedAt`，开始组间休息。
- 点组行其他区域：打开 `SetEditorSheet`，可以：
  - 完成
  - 未完成（填实际次数/重量）
  - 跳过
  - 写备注 + 快捷标签（力竭/重量偏大/动作变形/时间不够）
- 只有从 pending 变成 done/partial 才触发休息；修改已完成组的备注/数值不会重复开始休息。
- 跳过不触发休息；如果当前休息计时属于该组，会被取消。
- 可「添加一组」；训练中也可「添加动作」。

### 7.5 结束训练

- 顶部「结束」打开结束弹层，显示时长、完成动作、完成组数、总容量。
- 结束会：
  - 把所有剩余 pending 组标记为 `skipped`
  - session 置 `completed`，写 `endedAt`
  - 清空休息计时
- 「放弃本次训练」会删除 session，不保存。
- 训练计时从确认页「保存并开始训练」开始，到结束为止；中断 App 后仍可从 `startedAt` 恢复。

### 7.6 历史与再次训练

- 同一天允许存在多条 completed 记录；日历标记优先显示 active/planned，否则显示最新 completed，并显示其计划名。
- 当天页展示所有已完成记录；可展开动作查看每组实际值、状态和备注。
- 动作趋势只取用户计划里的动作。示例计划带 `sample: true`，默认不计入；用户开始/结束/编辑并保存示例计划后会把 `sample` 置为 false，之后才进入趋势范围。正在训练的示例计划也会通过 active session 带入趋势。
- 「再练一次」优先复用原计划模板；模板已删除时，用这次实际记录生成新计划，然后进入确认页。
- 「另存为计划」把实际记录转成可复用模板。
- 部分完成的组在记录摘要显示为 `数字*`，旁有图例；展开可看到实际次数和备注。

## 8. 休息计时与通知

### 8.1 计时

- `RestTimerBar` 从 Store 的 `restTimer.endsAt` 计算剩余时间，不依赖 setInterval 累加，切后台不会漂移。
- 可 -15s / +15s / 跳过；调整会取消旧通知并重新调度。
- 计时结束显示「休息结束」和下一组/下一动作文案。
- 休息文案由 `nextActionLabel` 生成：
  - 同动作有后续组 → 「动作名 第N组 · 重量 × 次数」
  - 没有后续组但还有其他动作 → 「下一动作：动作名」
  - 全部完成 → 「所有动作已完成，记得结束训练」

### 8.2 系统通知

- 使用 `@capacitor/local-notifications`。
- 完成一组时按 `endsAt` 预约本地通知；通知内容带下一组或下一动作。
- 通知点击监听在 `App.tsx`，有 `sessionId` 时跳回训练页。
- Android 8+ 使用通知渠道区分声音/震动组合：
  - `rest-both`、`rest-sound`、`rest-vibrate`、`rest-silent`
  - 渠道定义在 `src/lib/notifications.ts`
  - 声音文件 `android/app/src/main/res/raw/rest.wav` 已放入并打包，由 `scripts/generate-notification-sound.mjs` 生成
- 当前使用 `isExactNotification: false`（非精确闹钟），避免首次使用弹出系统「精确闹钟」授权页；锁屏提醒可能受系统省电策略影响。
- 通知权限：
  - PC 浏览器需允许浏览器通知。
  - Android 13+ 需 `POST_NOTIFICATIONS`，App 在开始训练/设置授权时请求。
  - 权限未授予时，仍保留应用内倒计时与应用内提示音/震动兜底。
- 通知是否成功调度会写回 `restTimer.notificationScheduled`；未成功时 `RestTimerBar` 在到点时播放应用内提示音/震动。

### 8.3 通知/音效设置

- `settings.soundEnabled` / `settings.vibrationEnabled` 决定使用哪个通知渠道，也决定应用内提示音/震动。
- 系统通知渠道的声音/震动创建后由 Android 管理；用户仍可在系统设置中单独关闭。

## 9. 本地持久化与导入导出

### 9.1 持久化

- Zustand `persist` + localStorage，键名 `workout-log-data-v1`。
- 持久化字段：plans / sessions / bodyMetrics / settings / customExercises / restTimer。
- Toast 不持久化；页面刷新后训练中断状态仍保留。
- 数据量小（文本 JSON），localStorage 足够；清除站点数据/卸载会丢失。

### 9.2 导出

```json
{
  "app": "workout-log",
  "version": 1,
  "exportedAt": "ISO 时间",
  "plans": [],
  "sessions": [],
  "bodyMetrics": [],
  "customExercises": [],
  "settings": {}
}
```

- PC：Blob 下载。
- Android：`@capacitor/filesystem` 写入 Documents，再调 `@capacitor/share` 分享/保存。
- 建议定期导出，作为换机和升级前备份。

### 9.3 导入

- 使用隐藏 `<input type="file">` 选择 JSON。
- `parseImportBundle` 校验顶层结构、计划、训练、身体数据、版本号（>1 拒绝）。
- 两种模式：
  - **合并**：按 `id` 去重，保留现有记录。
  - **覆盖**：替换计划/训练/身体数据/自建动作，设置合并默认值。
- 导入前会取消当前休息通知。

## 10. 日历与日期

- 周一为每周第一天，固定生成 42 格（6 周）。
- 日期统一使用本地时区的 `YYYY-MM-DD` 字符串；比较直接用字符串。
- 日期点击规则：
  - 有 active → 训练页
  - 有 planned/记录 → 当天页
  - 今天/未来且无数据 → 选计划页
  - 过去且无数据 → 当天页空态
- 今天条固定在日历上方，显示当前状态并提供快捷按钮。
- 示例数据中的日期都相对于“今天”生成，避免写死日期。

## 11. 样式、动效与性能

- 主题变量在 `src/styles/tokens.css`；深色运动风 + 荧光绿强调色。
- 移动端全屏；宽度 ≥600px 时显示为居中的 520px 手机框。
- 页面切换为 CSS 淡入/位移；月历切换有左右方向动画；底部弹层有上滑/下滑；休息条有上浮。
- 数字使用等宽/表格数字，避免倒计时抖动。
- SVG 图表按 360×180 坐标绘制，随宽度缩放。
- 计时组件只在局部 setState（1s/0.5s），不把计时写入全局 Store，避免整页重渲染。
- 当前生产构建约：JS 297KB、CSS 47KB（未压缩），另有 Capacitor 插件 web chunk；无重型第三方图表/动画库。
- 最终 release APK 为 3.36 MB，体积主要来自 Capacitor 原生壳和 Android 资源。

## 14. 常见开发坑

- **不要在条件分支里调用 Hooks**：例如 `PlanEditorPage` 中 `plan` 查询必须始终调用 selector，再根据 `planId` 取结果。
- **计划快照**：确认页修改只影响本次 session，不要误调用 `savePlan`；否则模板会被改。
- **休息通知**：调整/跳过/提前完成时必须取消旧通知，再按新 `endsAt` 调度；通知 id 变化时注意旧异步回调不要覆盖新计时器（代码用 `state.restTimer?.id === timer.id` 防竞态）。
- **日期**：所有日期用本地 `YYYY-MM-DD`，不要用 UTC 的 `toISOString().slice(0,10)`（已修复一处）。
- **重量 null** 表示自重；`0kg` 是合法的实际重量，不要混用 `null`/`0`。
- **BulkSetSheet** 的初始化依赖 `open`，避免输入时父组件重渲染把输入重置。
- **HashRouter** 是 Capacitor 静态资源的稳妥选择；不要随意改 BrowserRouter。
- **Web 通知** 与 Android 本地通知能力不同：浏览器关闭标签页后计时提醒不可靠，APK 才有系统级通知。
- **localStorage 数据** 仅存在于当前浏览器 Profile；测试版和 APK 的数据不互通，必须导出/导入。
- **示例数据** 使用固定 id，重复载入不会重复插入；清空数据会删除示例数据。
- **示例计划与趋势**：`sample: true` 的示例计划默认不计入动作趋势；开始/结束/编辑保存示例计划后会把 `sample` 置为 false，之后才计入。
- **JDK 版本**：Capacitor 8 的 Android 模块以 Java 21 编译，JDK 17 会报 `invalid source release: 21`；构建时必须使用 JDK 21。
- **Gradle/Maven 下载**：官方源较慢时，Gradle 用腾讯镜像、Maven 用 `android/aliyun.init.gradle`；否则依赖下载可能长时间无输出。
- **签名备份**：APK 用本地 `.jks` 签名，密码在 `android/keystore.properties`；两者丢失后无法用同一签名升级应用。
- **状态栏/返回键**：Android 端由 `@capacitor/status-bar` 和 `@capacitor/app` 处理；真机上要检查 Android 15 的 edge-to-edge 是否遮住页面顶部，以及硬件返回键在根页面是否正常退出。
- **精确闹钟**：插件合并了 `SCHEDULE_EXACT_ALARM`，但代码使用 `isExactNotification: false`；不会主动弹精确闹钟授权页，极端省电下可能延迟。
- **APK 资源路径**：release APK 中 AGP 会缩短 res 路径（如 `res/-B.png`），核对资源要用 `aapt2 dump resources`，不能只看 zip 文件名。
